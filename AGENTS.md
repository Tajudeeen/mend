# MEND engineering boundaries

Keep the host requirements in `docs/host-requirements.json` and `docs/HOST_REQUIREMENTS.md`. Preserve meaningful Qloo use, a working agentic app, public demo/source requirements, a detectable open-source license, written description, eligibility/registration, English/free testing access and finalist availability. All four judging criteria carry equal weight. A video is optional. Recheck official rules before submission.

Never treat local checks, fixtures, hashes or a configured key as proof of live Qloo access, provider authorship, public judge access or organizer impact. Do not remove pending gates during cleanup. Preserve licenses and required assets. Keep historical verification entries dated.

The core flow is event inputs → evidence → constrained proposal → explicit approval → persisted report. Agent tools cannot approve, book, spend or message. Unknown terms block live approval. Approved incidents remain current facts until deliberately edited. Search truncation must be disclosed.

The Node/Supabase/PostgreSQL target and Sites/ChatGPT/D1 compatibility target are distinct. Do not silently migrate saved data or identities. Keep credentials server-side.

Use `pnpm verify` for local repository, tests, benchmark, builds and Worker/D1 workflow checks. Its ignored report is `outputs/verification.json`; it does not certify external submission gates. Use `pnpm verify:report FILE` or `/verify` for source response integrity only.
